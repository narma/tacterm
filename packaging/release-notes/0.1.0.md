## Less GPU memory comes first

tacterm 0.1.0 is our first non-preview release: a Rio-based terminal focused on
lower GPU memory use, better tabs, and practical Windows and WSL improvements.

We reduced GPU memory reservations, removed unused rendering buffers, shared
render pipelines between panels, and made glyph textures start small and grow
only as needed. Existing glyphs survive growth without rebuilding the cache.

Development measurements on **Windows with an NVIDIA GeForce RTX 5080** show
the effect of individual optimization stages:

| Change and workload | Dedicated GPU memory before → after | Reduction |
| --- | --- | --- |
| Allocation and lazy-storage changes; one maximized terminal at idle, Vulkan | 398.6 → 234.5 MiB | 164.1 MiB / 41% |
| Growing color-glyph atlases; 10 tabs with mixed-language text and emoji, DX12 | 410.7 → 282.7 MiB | 128 MiB / 31% |
| Growing grayscale atlases; 10 text tabs at 1600 × 900 and 150% scaling, DX12 | 133.9 → 101.9 MiB | 32 MiB / 24% |

These are **separate before/after comparisons from development**, not additive
savings or a single upstream-versus-final-release benchmark. Each later stage
was compared with the already optimized previous build. Measurements used
Windows GPU process-memory counters, which include driver allocation pools;
the first comparison used four runs per version, and the two 10-tab comparisons
used two retained runs per version. Hardware, backend, window size and glyph
workload affect the result. Atlases retain their grown capacity, so demanding
workloads can still reach their previous maximum size. Lower memory use is not
a claim of higher FPS.

## Tabs that look right and keep your place

- Better Unicode tab titles, with improved font fallback, alignment and shaping.
  Set `tab-font-family` and `tab-font-size` independently of terminal fonts.
- New tabs preserve window dimensions and font size, fixing progressive loss of
  usable terminal space.
- WSL tabs can inherit the focused tab's working directory, with automatic zsh
  integration.
- Configuration reloads retain platform-specific overrides.

## Smoother presentation on Windows

Focused, visible fullscreen and maximized GPU windows continuously present
through the swapchain, reusing unchanged grid data. Timing fixes also preserve
fractional refresh rates. This is intended to provide steadier presentation on
VRR displays; it uses GPU resources while idle and still needs broader display
and GPU validation. Other window states keep event-driven rendering.

## A separate home for tacterm

The executable is now `tacterm` / `tacterm.exe` in both source builds and release
archives, with its own application icon.

On first launch, if the tacterm configuration directory is absent, settings,
themes and assets are copied from Rio. The original files remain unchanged.
Later loads and edits use tacterm's copy, with **no fallback to Rio**.

- Windows: `%USERPROFILE%\AppData\Local\tacterm`
- macOS: `~/.config/tacterm`
- Linux: `$XDG_CONFIG_HOME/tacterm`, or `~/.config/tacterm`

`TACTERM_CONFIG_HOME` overrides the destination; `RIO_CONFIG_HOME` only overrides
the import source. An existing destination, even empty, prevents reimport.
Logs and installer backups are excluded. Linked files require manual migration,
and absolute paths inside settings remain unchanged.

This replaces the shared-settings behavior of `0.1.0-alpha.1`.
